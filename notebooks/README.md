# Notebooks

Every run is driven by a notebook. Each one is **generated** — edit the generator, never the
`.ipynb` — so that the cells stay identical across arms and cannot drift apart.

```
notebooks/
  train/       one notebook per training run; each trains, then evaluates itself
  evaluate/    one notebook per evaluation-only run; pulls its checkpoint from the Hub
  figures/     the paper's data-driven figures (no training, no checkpoints)
  generators/  the source of truth for every notebook above
```

## figures/

| notebook | what it produces |
|---|---|
| `moe-of-sod__paper_figures.ipynb` | the three data-driven figures of `paper/main.tex`: the eight-arm qualitative grid, the threshold/P–R curves, and the decoder-stage progression |

Unlike the other two directories this is not a training or evaluation run: it reads the
archived per-image prediction maps from the Hub and the WXSOD ground truth, and writes
`figures/*.pdf` to copy into `paper/figures/`. It needs no GPU and retrains nothing.
The decoder-stage panel is the one part that needs a checkpoint; if it cannot load one the
notebook deliberately does **not** write that file, so `main.tex` shows its placeholder
instead of a wrong figure.

It publishes its output to the Hub under **`figures/paper/`**, alongside the per-arm
montages in `figures/qualitative/`, so the figures travel with the artifacts they came from:

```python
from huggingface_hub import snapshot_download
snapshot_download(repo_id="Avi2006/spatial-moe-results", repo_type="dataset",
                  allow_patterns="figures/paper/*")
```

Set `UPLOAD_TO_HUB = False` in `01_config` to run it without pushing.

## Regenerating

From the repository root:

```bash
python notebooks/generators/generate_notebook_variants.py    # everything except the two account notebooks and the legacy evaluation
python notebooks/generators/generate_notebook_accountA.py
python notebooks/generators/generate_notebook_accountB.py
python notebooks/generators/generate_notebook_legacy_eval.py
python notebooks/generators/generate_notebook_paper_figures.py
```

Regenerating with no source changes must leave the working tree clean — if `git status` shows
a modified notebook, the generator and the committed notebook had drifted apart.
`tests/test_notebook_generators.py` checks the same thing.

## Running one on Kaggle

Each notebook downloads the code zip and its checkpoint from Hugging Face, so it is
self-contained. Set `RUN_MODE` at the top of the first cell:

- `TRAIN` — train from scratch, then evaluate. Refuses to start if the run's checkpoints
  already exist, so a finished run cannot be silently overwritten; set `ALLOW_OVERWRITE = True`
  to redo one on purpose.
- `EVALUATE` — pull this run's checkpoint and score it, no training.
- `RESUME` — continue an interrupted run from its latest checkpoint.

## Review-response notebooks (two runs, one evening)

Generated by `generators/generate_notebook_bootstrap_and_router.py` and
`generators/generate_notebook_router_confidence.py`. Run both **in parallel** on Kaggle.

### 1. `statistics/moe-of-sod__bootstrap_and_router_forensics.ipynb` — no training

Answers the reviewer's two analysis objections. Takes minutes.

- Recomputes **per-image** MAE for all 14 arms from the saved prediction maps on the
  Hub (8-bit PNG, so ~1/255 quantisation; common-mode across arms, so paired
  differences are unaffected — the notebook prints the recomputed-vs-JSON delta so the
  size of the discrepancy is on the record).
- **Paired bootstrap** (20 000 resamples) and a **TOST** equivalence test against an
  explicit margin of 0.001. This is what licenses the phrase "no effect"; a
  non-significant difference alone does not.
- Recomputes the **seed floor** with the same estimator on the same image set, from
  `seed43`/`seed44`, instead of quoting a single number.
- **Router forensics**: routing entropy at initialization versus after training
  (fresh models at five seeds vs the trained checkpoint), router gradient norm share
  against experts/decoder/backbone, and the cosine similarity of the **branch**
  difference `E_a − E_b` rather than the full outputs — the residual `x` is shared, so
  the full-output cosine is inflated.

Uploads to `analysis_results/bootstrap_tost/` and `figures/paper/`.

Needs: the source zip on the Hub at `code/spatial_moe_sod_code.zip` and
`checkpoints/best.pth`. If the source is not there, attach the repo as a Kaggle input
and set `REPO_ROOT` in the "model source" cell.

### 2. `training/moe-of-sod__router_confidence_arm.ipynb` — 8 epochs × 2 arms

Answers *"the MoE was never given a fair chance."* The loss term exists
(`src/loss.py`, `src/config.py`); `experiments/v_4expert_entropyconf.json` sets
`entropy_confidence_weight: 0.2` at the family recipe. It has since been run as
`CONF02` (w=0.2) against the matched `CONF00` control (w=0.0), archived under
`analysis_results/EXP_B4_E4_K2_S40_R1_L3_M_SPARSE_ENTROPYCONF/` and
`analysis_results/EXP_B4_E4_K2_S40_R1_L3_M_SPARSE_ENTROPYCONFCTRL/`. It is
uninformative by construction --- the objective is the mean normalised entropy, whose
gradient vanishes at the uniform gate --- so it is reported as such, not as a failed
remedy.

Runs two arms differing in exactly one field: `CONF02` (weight 0.2) and `CONF00`
(matched control, weight 0.0). Set `RUN_CONTROL = False` to halve the GPU cost at the
price of a non-matched comparison.

Uploads the run directory, checkpoint, evaluation outputs including per-image
predictions, and the exact `arm_config.json` to `analysis_results/<EXP_ID>/` and
`checkpoints/<EXP_ID>/`.

### Reading the results

The confidence arm only counts as a fair chance if it moved *something*: normalised
entropy off the ceiling, a measurably different hard expert-usage histogram, or a
router gradient-norm share above the control's. Pass per-image errors into notebook 1
before claiming any MAE difference.
